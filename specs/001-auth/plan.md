# Implementation Plan: Authentication

**Branch**: `001-auth` | **Date**: 2026-04-22 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-auth/spec.md`

## Summary

Implement the authentication module for the VideosYT platform. Users (ADMIN or VIEWER) log
in with email/password and receive a JWT access token (15 min) + refresh token (7 days).
Silent token rotation keeps sessions alive. Replay attack detection invalidates all sessions
on suspicious token reuse. Rate limiting caps login attempts at 5/min/IP. Built as an
isolated NestJS module using Passport.js (JWT strategy), bcrypt, @nestjs/throttler, and
Prisma for refresh token persistence.

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js 20 LTS
**Primary Dependencies**:
- Backend: `@nestjs/jwt`, `@nestjs/passport`, `passport-jwt`, `bcrypt`, `@nestjs/throttler`, `@nestjs/swagger`, `class-validator`, `class-transformer`, `prisma`
- Frontend: `axios` (interceptor-based silent refresh), React Context (in-memory token storage)

**Storage**: PostgreSQL via Prisma ORM — `User` and `RefreshToken` tables
**Testing**: Jest + `@nestjs/testing`
**Target Platform**: Linux server (Railway) — single-instance deployment
**Project Type**: web-service (REST API module + Next.js frontend integration)
**Performance Goals**: Login response < 500ms p95 under MVP load (~50 concurrent users)
**Constraints**: bcrypt cost factor = 10; rate limit 5/min/IP; access token in memory only
**Scale/Scope**: ~50 users MVP

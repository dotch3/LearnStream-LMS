# Implementation Plan: Course Enrollment System

**Branch**: `009-course-enrollment` | **Date**: 2026-04-28 | **Spec**: [spec.md](./spec.md)

## Summary

Adds a full enrollment gate to all course content. Users must be explicitly enrolled (APPROVED status) to access track detail and video content. Two enrollment paths: admin-mediated request/approve flow and instant code redemption. Track visibility replaces the boolean `isActive` with a three-state enum. In-platform notifications with a sidebar bell close the feedback loop for both users and admins.

## Technical Context

**Language/Version**: TypeScript 5.x / Node.js 20 LTS (backend + frontend)
**Primary Dependencies**: NestJS (backend), Next.js App Router (frontend), Prisma 7, class-validator, nodemailer (existing)
**Storage**: PostgreSQL via Prisma ORM — 4 new tables + Track schema change
**Testing**: Jest (backend unit), Playwright (E2E — planned, out of scope this feature)
**Target Platform**: Linux server (Railway) + Vercel (frontend)
**Project Type**: Web service + web application
**Performance Goals**: Standard web — notification badge polled per navigation
**Constraints**: No WebSocket; notifications are polled. Admin always bypasses enrollment.
**Scale/Scope**: ~50 users, ~20 courses (MVP)

## Constitution Check

- ✅ **I. Security-First**: EnrollmentGuard enforces APPROVED status before exposing video content. YouTube IDs never exposed to non-enrolled users.
- ✅ **II. RBAC**: ADMIN bypasses all enrollment checks. New routes use existing `@Roles(Role.ADMIN)` guard.
- ✅ **III. Data Integrity**: Enrollment status transitions are one-way except DENIED→PENDING re-request. No progress impact.
- ✅ **IV. Modular Architecture**: Three new NestJS modules (`enrollments`, `enrollment-codes`, `notifications`). Each exports only its service.
- ✅ **V. API-First**: All new endpoints get Swagger decorators and class-validator DTOs.
